Project Overview

A pitcher-batter matchup model and Shiny app built as my UCLA Statistics & Data Science senior capstone (Stats 141XP), with a Team Italy analytics staff member as the client. The goal was to give him a practical tool for lineup and bullpen matchup decisions ahead of the 2026 World Baseball Classic.

The model is trained on six years of MLB and AAA Statcast data (2020–2025) and predicts expected run value outcomes at the individual plate appearance level, assigning each matchup a score from 50–150 (100 = league average). It integrates pitch-type-specific whiff, run value, hard hit, and barrel interactions across nine pitch types alongside a Log5-derived baseline, delivered through a custom R Shiny matchup sheet app.

Post-tournament validation across 47 WBC games and 3,509 plate appearances showed bucketed OPS and Delta Run Expectancy correlations of r = 0.976 and r = 0.971 against model scores — a genuine out-of-sample test on a competition the model had no exposure to during training.

Key Features

1

Pitch-Type Interaction Features

For each of nine pitch types (FF, SI, FC, SL, ST, CU, KC, CH, FS), the model combines pitch usage rate with pitcher and batter performance metrics — whiff rate, run value, hard hit rate, and barrel rate — creating 36 dedicated interaction terms that capture how a specific batter's tendencies match up against a specific pitcher's arsenal.

2

Log5 Baseline

Each matchup is anchored to a Log5 expected outcome derived from pitcher and batter overall quality percentiles, scaled relative to league-average run expectancy. This prevents the model from overfitting to small-sample pitch-level features in isolation and grounds predictions in true talent signals.

3

Handedness Splits

All pitcher and batter features are computed separately for same-hand and opposite-hand matchups. Platoon effects are modeled explicitly as features, and the final score reflects the appropriate split for the specific pitcher-batter combination being evaluated.

4

Velo & Spin Advantages

For the primary pitch types (fastball, slider, curveball), velocity and spin rate are compared against league-average benchmarks to quantify stuff advantage above or below expectation — capturing pitcher quality beyond run value alone.

5

Swing Decision Interaction

An exit velocity vs. chase rate term combines a batter's raw contact quality with their out-of-zone swing tendencies, capturing the difference between high-contact hitters who protect the plate versus swing-happy power hitters more susceptible to chasing.

6

Interactive Shiny App

Model predictions feed a Shiny matchup sheet generator built in R, with an Italia/WBC theme supporting Italy-vs-opponent lineup construction. Coaches can select the opposing pitcher and see all Italian batters ranked by predicted matchup score, with exportable color-coded Excel output.

Technical Implementation

Data Pipeline

The pipeline runs in five sequential R scripts, each building on the previous output:

  1. Data Collection (01_collect_data.R): Downloads all MLB (2020–2025) and AAA (2023–2025) pitch-level Statcast data via Baseball Savant's API in 3-day chunks to stay under the 25K-pitch-per-request limit, with automatic retry logic and progress reporting.
  2. Processing (02_process_data.R): Cleans raw data, standardizes delta run expectancy columns across API schema changes, and filters to regular-season plate appearances.
  3. Quality Metrics (03_build_quality.R): Computes per-player pitcher and batter quality percentiles using a pnorm-scaled delta RE approach — the basis for Log5 prior probabilities.
  4. Feature Engineering (04_build_features.R): Builds per-player, per-handedness pitch-type features (usage rate, whiff rate, run value, hard hit rate, barrel rate, velocity, spin) for all pitchers and batters meeting minimum PA thresholds.
  5. Training (05_train_model.R): Assembles matchup-level training data (≥20 pitches per pitcher-batter-season pair), joins features, and trains XGBoost (eta = 0.05, max_depth = 6, 500 rounds) on the 2020–2024 holdout split first, then retrains on 2020–2025 for the final deployment model.

Score Calibration

Raw XGBoost predictions (in units of delta run expectancy per PA) are linearly rescaled relative to a 0.15 runs-per-PA baseline and shifted to center around 100, then clamped to the 50–150 range. A score of 125+ corresponds to a matchup predicted to produce OPS in the 1.9+ range in WBC validation; a score below 75 corresponds to near-zero or negative expected run value.

WBC Adaptation

Because WBC players only have a few games of tournament data, the validation pipeline (validate_wbc_2026.R) merges small-sample WBC features with each player's existing MLB/AAA history for prediction. Players with no prior MLB/AAA record are excluded from app predictions to prevent noise from single-game WBC samples from inflating matchup scores.

Interpreting the Correlations

The low PA-level and matchup-level correlations (r ≈ 0.37–0.39) are expected — individual plate appearance outcomes are inherently noisy, and single matchup samples are small. The meaningful signal is in the bin and bucket aggregations: when PAs are grouped by predicted score, actual delta run expectancy rises monotonically across every bin (r = 0.971), and OPS by score bucket follows the same pattern (r = 0.976). The model reliably ranks matchup quality even in a tournament it was never trained on.

Design Decisions & Learnings

Why Pitch-Type Interactions Instead of Arsenal-Level Features

Rather than summarizing each pitcher's arsenal into a single "stuff score," the model builds separate interaction terms per pitch type — combining how often the pitcher throws it, how well they throw it (run value, whiff), and how the batter performs against that specific pitch type. This lets the model capture matchups where a pitcher's best pitch is exactly the batter's weakness, rather than flattening that signal into averages.

Separating Validation from App Features

The WBC validation pipeline deliberately uses unfiltered WBC features (all PAs, even tiny samples) for generating predictions to validate against, while keeping the app's player database filtered to players with ≥10 MLB/AAA PAs per handedness split and no WBC-only records. This separates "can the model predict WBC outcomes" from "should WBC noise enter future app predictions."

Two-Stage Training Strategy

Training first on 2020–2024 and validating on 2025 confirmed the model generalizes across seasons before retraining on all six years for the final deployment model. This prevents the common error of only ever evaluating on training data while still using the full data for the model coaches actually use.

Future Directions

  • Extend the model to include batted ball location tendencies (pull/oppo/center splits) for deeper fielding shift matchup context
  • Incorporate recency weighting to down-weight early career seasons in feature computation
  • Build confidence intervals around matchup scores using quantile regression or conformal prediction
  • Expand the Shiny app to support full lineup optimization across an opponent's probable bullpen
