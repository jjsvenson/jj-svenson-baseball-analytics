Project Overview

A pitcher-batter matchup model and Shiny app built as my UCLA Statistics & Data Science senior capstone (Stats 141XP), with a Team Italy analytics staff member as the client. The goal was to create a practical tool for lineup and bullpen matchup decisions ahead of the 2026 World Baseball Classic.

The model is trained on six years of MLB and AAA Statcast data (2020–2025) and predicts expected run value outcomes at the individual plate appearance level, assigning each matchup a score from 50–150 (100 = league average). It integrates pitch-type-specific whiff, run value, hard hit, and barrel interactions across nine pitch types alongside a Log5-derived baseline, delivered through a custom R Shiny matchup sheet app.

Post-tournament validation run across all 47 WBC games in the dataset — 3,509 plate appearances spanning all teams and matchups — showed bucketed OPS and Delta Run Expectancy correlations of r = 0.976 and r = 0.971 against model scores, with actual outcomes rising monotonically across every score bin.

Key Features

1

Pitch-Type Interaction Features

For each of nine pitch types (FF, SI, FC, SL, ST, CU, KC, CH, FS), the model builds four interaction terms, combining the pitcher's usage rate with matched pitcher-batter metrics: whiff rate, run value per pitch, hard hit rate, and barrel rate. This produces 36 pitch-type interaction features alongside pitch percentage columns, velocity and spin advantage terms, and several batter-level features — capturing how a specific batter's tendencies line up against a specific pitcher's arsenal pitch by pitch.

2

Log5 Baseline

Each matchup is anchored to a Log5 expected outcome derived from pitcher and batter overall quality percentiles, scaled relative to league-average run expectancy. This prevents the model from overfitting to small-sample pitch-level features in isolation and grounds predictions in true talent signals.

3

Handedness Splits

All pitcher and batter features are computed separately for same-hand and opposite-hand matchups. Platoon effects are modeled explicitly as features, and the final score reflects the appropriate split for the specific pitcher-batter combination being evaluated.

4

Velo & Spin Advantages

For the primary pitch types (fastball, slider, curveball), velocity and spin rate are compared against league-average benchmarks to quantify stuff advantage above or below expectation — capturing pitcher quality beyond run value alone.

5

Swing Decision Interaction

An exit velocity vs. chase rate term combines a batter's raw contact quality with their out-of-zone swing tendencies, capturing the difference between high-contact hitters who protect the plate versus swing-happy power hitters more susceptible to chasing.

6

Interactive Shiny App

Model predictions feed an R Shiny app with two main views: a general matchup page where any two WBC rosters can be compared head-to-head, and an Italy-specific scouting page where coaches can generate exportable, color-coded matchup sheets ranking Italian batters against an opposing team's pitchers, and vice versa.

Technical Implementation

Data Pipeline

The pipeline runs in five sequential R scripts, each building on the previous output:

  1. Data Collection (01_collect_data.R): Downloads all MLB (2020–2025) and AAA (2023–2025) pitch-level Statcast data via Baseball Savant's API in 3-day chunks to stay under the 25K-pitch-per-request limit, with automatic retry logic and progress reporting.
  2. Processing (02_process_data.R): Cleans raw data, searches for the delta run expectancy column by checking several possible names Baseball Savant has used across API versions (`delta_run_exp`, `delta_run_exp_bat`, `run_exp_change`, `delta_home_run_exp`), and filters to regular-season plate appearances. Falls back to event-based run value approximations if no matching column is found.
  3. Quality Metrics (03_build_quality.R): Computes per-player pitcher and batter quality percentiles using a pnorm-scaled delta RE approach — the basis for Log5 prior probabilities.
  4. Feature Engineering (04_build_features.R): Builds per-player, per-handedness pitch-type features (usage rate, whiff rate, run value, hard hit rate, barrel rate, velocity, spin) for all pitchers and batters meeting minimum PA thresholds.
  5. Training (05_train_model.R): Assembles matchup-level training data (≥20 pitches per pitcher-batter-season pair), joins features, and trains XGBoost (eta = 0.05, max_depth = 6, 500 rounds) on the 2020–2024 holdout split first, then retrains on 2020–2025 for the final deployment model.

Score Calibration

Raw XGBoost predictions (in units of delta run expectancy per PA) are linearly rescaled relative to a 0.15 runs-per-PA baseline and shifted to center around 100, then clamped to the 50–150 range. Anything above 100 is an advantage to the hitter and anything below 100 is an advantage to the pitcher.

WBC Validation

For validation, WBC Statcast CSVs were processed using the same feature-building logic as the main pipeline and appended to the existing historical feature database, creating a combined dataset covering 2020–2026. The model then generated predictions for every WBC plate appearance using this combined feature set — so for a player with five years of MLB history, their WBC predictions draw on all of that context, not just their handful of WBC games.

The app's player database works differently: it uses only pre-2026 MLB and AAA data (≥10 PAs per handedness split), keeping small WBC samples out of the prediction features entirely to avoid inflating barrel and hard-hit rates on tiny samples from players who may have had one hot WBC game.

Interpreting the Correlations

The PA-level and matchup-level correlations (r ≈ 0.37–0.39) reflect the inherent noise in individual plate appearance outcomes — no model predicts single PAs reliably, and that's not the goal. The key finding is in the aggregations: when PAs are grouped by predicted score, actual delta run expectancy rises monotonically across every bin (r = 0.971), and OPS by score bucket follows the same staircase pattern (r = 0.976). The model consistently separates good matchups from bad ones across a tournament it was never trained on.

Design Decisions & Learnings

Why Pitch-Type Interactions Instead of Arsenal-Level Features

Rather than summarizing each pitcher's arsenal into a single "stuff score," the model builds separate interaction terms per pitch type — combining how often the pitcher throws it, how well they throw it (run value, whiff), and how the batter performs against that specific pitch type. This lets the model capture matchups where a pitcher's best pitch is exactly the batter's weakness, rather than flattening that signal into averages.

Keeping Validation and App Features Separate

For validation, WBC features are appended to the historical database so predictions reflect each player's full career context — not just their few WBC games. The app's player database is handled differently: it uses only pre-2026 MLB and AAA data with a ≥10 PA per handedness split minimum, keeping WBC samples out entirely. A player who went 4-for-8 with three home runs in the WBC won't have that inflate their app score; the app reflects their actual MLB/AAA track record.

Two-Stage Training Strategy

Training first on 2020–2024 and validating on 2025 confirmed the model generalizes across seasons before retraining on all six years for the final deployment model. This prevents the common error of only ever evaluating on training data while still using the full data for the model coaches actually use.

Future Directions

  • Extend the model to include batted ball location tendencies (pull/oppo/center splits) for deeper fielding alignment matchup context
  • Incorporate recency weighting to down-weight early career seasons in feature computation, better reflecting a player's current form
  • Build confidence intervals around matchup scores so coaches can distinguish high-confidence predictions from noisy ones
  • Add count-specific features (pitcher tendencies and batter performance in hitter's counts vs. pitcher's counts) to capture in-PA decision-making context
  • Incorporate pitch location and tunneling metrics
  • Extend to minor league contexts by testing whether the model trained on MLB/AAA data holds predictive validity when applied to lower-level player features
